# 21 — Testing FORGE Itself

FORGE enforces a test discipline on the systems it builds. It is held to the same standard, and this
file is that standard made concrete. Where `13` describes the frameworks FORGE *applies*, this file
applies them to FORGE.

## 21.1 Strategy

| Layer | Scope | Target | Speed | Tooling |
|---|---|---|---|---|
| Unit | Pure logic: schema validation, merge semantics, expression evaluation, scheduling decisions, ID allocation, redaction, parsers | ~65% of tests | < 5 ms each | vitest |
| Integration | Package-to-package with a real filesystem and real git, using the fake adapter | ~25% | < 500 ms each | vitest + `tmp` dirs + real `git` |
| TUI | Rendered frames and key-driven interactions | included above | < 100 ms each | `ink-testing-library` |
| Conformance | The adapter suite (`07` §7.6) against each adapter | 16 tests × adapters | varies | vitest, live for real adapters |
| E2E | Full runs against fixture projects, no network, fake adapter | ~8% | < 60 s each | vitest + fixture harness |
| Live | A small suite against a real platform, nightly and pre-release | ~2% | minutes | vitest, gated by credentials |

**Coverage:** 90% lines / 85% branches on `core`, `schemas`, `kb`, `engine`, `extensions`, `vcs`
(the correctness-critical packages); 80/70 elsewhere; ratchet-only (`13` F-TEST-5). Mutation testing
nightly on `core`, `engine`, `extensions`, `schemas`.

**Determinism is mandatory.** Injected clock, seeded RNG (`--seed` exists partly for this), fixed
timezone (`TZ=UTC`), no reliance on filesystem ordering, `git` identity pinned in test setup. The
scheduler's tie-breaking must be reproducible given a seed — a flaky scheduler test means the
scheduler is non-deterministic, which is a bug in the scheduler.

**Network is denied in unit and integration tests** by an undici/fetch interceptor that throws on any
outbound request. This catches accidental network dependencies, which are the main cause of test
suites that work on the author's machine.

## 21.2 Fixture projects

`fixtures/` contains committed sample host projects used by e2e tests:

| Fixture | Purpose |
|---|---|
| `empty/` | Bare directory for `init` |
| `greenfield-service/` | Expected output of an L2 service init; the golden target for `init` + `plan` |
| `brownfield-small/` | ~3k LOC TS service with deliberate defects: a shared-write table, an undocumented component, a broken README build command, a secret-looking string, a cyclic import |
| `brownfield-polyglot/` | TS + Python + a Dockerfile, for adoption scoping |
| `mid-run/` | A project with a half-complete run and a populated event log, for resume tests |
| `corrupt-state/` | Truncated event log, stale lock, orphaned worktree, drifted index — for `doctor` |
| `customized/` | Overlays, skills, MCP config, a preset, and one deliberately invalid overlay per invariant |
| `diagram-drift/` | Generated diagrams intentionally out of sync with their sources |

Fixtures are regenerated by a script and committed, so changes to them are reviewable diffs.

## 21.3 Required test suites by area

### Schemas and migrations
- Every schema: valid fixture passes, invalid fixture fails **with the expected error path**
  (asserting the error path prevents schemas that accidentally accept everything).
- Every migration: golden-file `before` → `after` using a real artifact; reversible migrations
  round-trip; migration chains apply in order across two major versions.
- Config: precedence order across all five layers; `config explain` reports the correct source layer
  for every key in a layered fixture.

### Customization / extensions (`15`, `19`)
- Merge semantics: every operator (`$set`, `$append`, `$prepend`, `$remove`, `$replaceWhere`,
  `$clear`) with nested cases and operator ordering; unknown operator is an error, never ignored.
- Layer resolution: five-layer fixture, per-field provenance asserted.
- **One test per invariant I1–I12** (`15` §15.10), each using a malicious or careless overlay fixture
  and asserting the specific error code. This is required, not optional — the invariants are the
  product's integrity claim.
- Upgrade safety: overlays survive a minor upgrade; a stale target is reported with a base diff and
  the run refuses to start.
- Preset eject: `apply <preset> --eject` produces overlays whose resolved output is byte-identical to
  direct application.
- Skill validation: size caps, dead references, injection-shaped content refused, `provides_checks`
  executed.

### Engine and scheduler (`06`, `10`)
- Plan compilation: fanout expansion, implicit dependencies from contract freeze and resource claims,
  cycle detection with a rendered graph, critical-path computation.
- Scheduling: ready-set ordering under a fixed seed; concurrency limits; exclusive agents; backpressure
  on simulated rate limits (concurrency halves, then recovers).
- Resource claims: overlapping `produces` serialise; two `exclusive` claims on the same glob fail
  compilation.
- Failure classification: each class in `06` §6.8 routes to its documented handling.
- Anti-thrash: two identical normalised fix diffs force escalation rather than a third attempt.
- Budget: admission control refuses a step that cannot fit; period budgets block new runs; retries
  attributed to the originating step.

### VCS and lanes
- Worktree create/remove; branch naming; cleanup on success, failure and crash.
- Merge queue: clean merge, conflict → agent resolution path, conflict → human path, post-merge
  failure → automatic revert + diagnostician scheduled.
- Out-of-claim writes reverted in `strict`, flagged in `warn`.
- Shared mutable paths: `serialize`, `regenerate`, `append-only` strategies each verified.
- **Dirty working tree halts the run** and never discards user work (`20` S8).

### Knowledge Body (`08`)
- Entry parse/write round-trip preserving formatting; atomic write under simulated crash.
- Linter: one test per rule, positive and negative.
- Contradiction detection: deterministic antonym pairs flagged; LLM-only findings produce warnings,
  never gate failures.
- Retrieval: structural inputs always present; lexical ranking stable; pack budget respected; pinned
  core never evicted.
- ID allocation: never reuses a deleted id; concurrent allocation within a run is serialised.

### Diagrams (`08` §8.11)
- Parse valid/invalid Mermaid for each diagram kind in the taxonomy.
- Every generator: fixture in → expected `.mmd` out (golden file).
- Drift detection: `diagram-drift` fixture fails; `autofix` policy regenerates; `warn` policy warns.
- Complexity budget, caption/alt-text requirement, transclusion mismatch, node-reference resolution.
- Rendering fallback produces self-contained HTML with **no network access** during render.

### Adapters (`07`)
- The 16-test conformance suite runs against: the fake adapter (must pass all), the generic
  declarative adapter with a scripted binary, and — in the live suite — real Claude Code.
- Degradation: for each capability turned off, the documented fallback is exercised and asserted.
- Process hygiene: abort terminates the whole child process tree; no orphans after a hard kill
  (asserted by scanning for children of the test process).

### Security (`20`)
- One test per invariant S1–S12, each written as an attack rather than a happy path: symlink escape,
  `..` traversal, denylist command composed with `&&`, secret in a diff, injected control token in an
  MCP result, tainted step attempting gate approval, overlay exceeding a ceiling.
- Redaction: a known secret value injected into every event payload type and asserted absent from
  disk after a full fixture run.

### TUI (`04`)
- Frame snapshots at 80×24, 100×30 and 120×40 for every screen in every canonical state.
- Key-sequence tests: scripted input produces the expected engine command list against a mock.
- Event replay: a recorded NDJSON run produces a golden final frame.
- Resilience fuzz: 10 000 random resize + key events, asserting no crash and no unhandled rejection.
- Degradation: `NO_COLOR`, `TERM=dumb`, `--ascii`, `--linear` each render without error.

### End-to-end
| # | Scenario | Asserts |
|---|---|---|
| E1 | `init` on `empty/` with an idea file, `--yes` | Full artifact set produced; `spec validate`, `kb lint`, `diagram validate` clean |
| E2 | `plan stage mvp` then `run build --stage mvp` with the fake adapter, 3 lanes | Lanes execute in parallel, merge in order, gates evaluate, final tree builds and tests pass |
| E3 | **Crash-resume** — `SIGKILL` at 20 randomised points during E2 | Resume completes; final state identical to an uninterrupted run; no duplicated commits, artifacts or ledger entries |
| E4 | Gate failure | A failing deterministic check blocks approval; waiver requires reason + expiry; the failure and waiver appear in the gate report |
| E5 | `adopt` on `brownfield-small/` | Every seeded defect appears in the gap report; no claim exceeds `confidence: medium` without evidence; build/test verification actually ran |
| E6 | Customization | `customized/` compiles; each invalid overlay produces its specific error code; a skill and an MCP grant reach the session |
| E7 | Debug loop | A seeded defect is reproduced, diagnosed, fixed, and a regression test is added, with an `RCA-###` containing a prevention action |
| E8 | Budget breach | Run pauses at the cap with a correct breakdown; `finish-lanes` and `abort` both behave as documented |
| E9 | Platform swap | The same stage runs on the fake adapter and the generic adapter with identical artifacts produced |
| E10 | Doctor | `corrupt-state/` is diagnosed; `--fix` and `--rebuild-index` restore a working project |

**E3 is the single most important test in this file.** Resumability is the guarantee the whole
orchestration model rests on, and it is only real if it is tested adversarially.

## 21.4 The live suite

A small suite that spends real money, run nightly and before every release, gated by credentials
being present (skipped, not failed, when absent):

- Adapter conformance against real Claude Code (both `sdk` and `cli` transports).
- One `init` + one small `implement-story` end to end, asserting artifacts validate and the produced
  code builds and tests green.
- Cost ledger accuracy: reported spend within 5% of the sum of adapter-reported costs (SC8).
- Model tier resolution against the live model list.

Live-suite flakes are triaged as **environment or product**, never ignored: an adapter that
intermittently fails is an adapter bug or a missing retry, and both are actionable.

## 21.5 Non-functional tests

| Property | Target | Test |
|---|---|---|
| Cold start | `npx forge-method --version` < 1.5 s warm cache | Benchmark in CI, ratcheted |
| First frame | `forge status` < 400 ms on a 100-artifact project | Benchmark |
| Compile | Full layer resolution < 1 s on a 5-layer fixture | Benchmark |
| KB pack | Context pack assembly < 300 ms at 500 entries | Benchmark |
| Index rebuild | < 5 s at 1000 entries | Benchmark |
| Memory | Supervisor RSS < 400 MB with 4 lanes streaming | E2E assertion |
| Bundle size | CLI bundle under the agreed ceiling | Size check, ratcheted |

Performance regressions fail CI via ratchet, because "it got slower gradually" is how tools become
unpleasant.

## 21.6 CI matrix

| Axis | Values |
|---|---|
| OS | ubuntu-latest, macos-latest, **windows-latest** |
| Node | 20, 22, 24 |
| Suites | unit + integration everywhere; e2e on ubuntu only (all Node versions); live nightly on ubuntu |

Windows is not optional. Path handling, worktrees, process trees and line endings all differ, and a
tool that fails on Windows loses a large share of its audience silently.

Additional CI jobs: `forge compile --check` on fixtures, dependency-boundary lint (`02` §2.2),
`pnpm audit`, mutation testing (nightly), bundle-size check, and a **schema-drift check** asserting
that emitted JSON Schemas match the committed ones.

## 21.7 Test quality rules for this repository

The rules FORGE imposes on generated projects apply here, and the implementer should expect them to
be enforced in review:

1. Tests assert against the **spec**, not the implementation. The standard: delete the
   implementation, rewrite it differently, and the tests still pass if behaviour is preserved.
2. Oracle discipline per `13` F-TEST-2 — no `toBeDefined()`-only assertions for a behaviour, no
   snapshots recorded without review.
3. Failure paths are tested at least as thoroughly as happy paths. For the engine, more so.
4. No shared mutable fixtures; factories with explicit overrides so each test names what matters.
5. Randomised test order in CI.
6. Every bug fixed during development gets a regression test named for its defect, and the RCA
   discipline in `13` F-DEBUG-1 applies to FORGE's own defects — including the prevention step.
